# 商品逐条录入与监控设计

## 目标

运营在同一页面通过「商品录入」和「商品扫描」两个标签切换，每次录入一个商品，保存后可在扫描页查询。首版覆盖商品资料录入和已接通的 Amazon 站点扫描。

## 方案选择

用户确认采用逐条表单，方便在保存前确认链接、站点和商品标识。备选是 Excel 粘贴或表格批量录入，适合大量导入，但需要逐行报错和批量去重，本版暂缓。

## 商品录入

| 字段 | 规则 |
|---|---|
| 序号 | 页面展示时从 1 递增，无需输入，不写入 MySQL |
| 平台 | Amazon、TikTok、Temu、eBay、SHEIN |
| 店铺代码 | 必填，下拉初始提供 H1-A1、H2-A1、H4-A1，实际完整清单可通过配置补充 |
| 站点 | DE、IT、FR、ES、GB、SE、BE、PL |
| ASIN | Amazon 商品从详情链接提取后展示给运营确认，与链接一致。其他平台允许留空 |
| SKU | 必填，填写店铺的商品 SKU |
| 商品名 | 必填，由运营输入 |
| URL | 必填，填写所选平台的 HTTPS 商品详情链接。Amazon 额外检查站点与域名一致，保留变体参数 |
| 配送邮编 | 可选，Amazon 可按站点预填，运营可修改。自定义值随商品保存，并由 MySQL 仓储读回供扫描使用 |
| 添加人 | 必选，Frank、Lvy、Nova、Drake。首版是录入归属字段 |

站点默认测试邮编按需求截图提供：DE 10115、IT 00174、FR 75001、ES 28001、GB SW1A 1AA、SE 111 22、BE 1049、PL 00-001。邮编使用字符串保存以保留前导零。录入成功后提示并提供「查看商品」，由运营手动发起扫描。

## 商品扫描

按序号、平台、店铺代码、站点、ASIN、SKU、商品名、URL、添加人展示商品资料，保留状态、最近扫描、耗时、OCR／截图证据和操作。站点、店铺代码下拉筛选，SKU 支持输入筛选，可组合使用。商品链接显示为可点击的「打开商品页」。技术故障原因在鼠标悬停或键盘聚焦状态旁的提示控件时显示，触屏可点开。

Amazon DE、IT、FR、GB 可以发起 Live。其他组合显示「暂未支持」，手动接口、告警复查和定时入口也应遵循相同限制。保存商品资料本身不发起扫描或告警。配送设置和加购判断沿用现有行为；配送未验证时，仍显示现有诊断。

## 存储与历史兼容

复用现有商品目录和 MySQL 仓储，新增录入接口与必要字段。MySQL 保留已有商品主键及扫描、告警、截图的关联。建议以「平台＋店铺代码＋站点＋SKU」判断重复；同 SKU 在不同店铺或站点可以分别录入。重复时提醒并定位现有商品，避免覆盖。

既有记录缺少店铺或添加人时显示「未填写」，不得猜测归属。既有目录启动同步应保留已保存的资料。实现计划需明确迁移、旧数据兼容以及并发录入去重的测试。本设计阶段不执行数据库迁移。

## 验收

- 从录入保存一条 Amazon 商品，刷新后仍可按店铺、站点和 SKU 查到，自定义邮编能由扫描侧读回。
- 同店同站同平台的重复 SKU 有提示，跨店铺或跨站点录入不会串历史。
- 保存尚未接通的平台或站点时可查询资料，不能误触发扫描或告警。
- 旧记录的历史、截图和告警仍能查看。技术错误详情支持悬停、键盘及触屏查看。
- 实现完成后运行自动化测试，再用新版分别执行健康与异常 Amazon Live 扫描各一次。
